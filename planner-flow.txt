❯ what Hyde generate and what is the use                                        

● What HyDE Is

  HyDE = Hypothetical Document Embedding

  It's a technique to improve RAG (retrieval) quality. Instead of searching the
  PDF with the user's raw short query, you first ask the LLM to write a fake 
  passage that would answer the query, then use that passage as the search
  query.

  ---
  What It Generates

  From hyde.py, it calls the LLM with this prompt:

  Generate a short hypothetical passage (3–5 sentences) that would be a perfect,
  highly
  relevant excerpt from a textbook or lecture notes answering this query.

  Example:

  User query: "explain gradient descent"

  HyDE generates something like:

  ▎ "Gradient descent is an iterative optimization algorithm used to minimize a 
  ▎ loss function. At each step, the algorithm computes the gradient of the loss
  ▎ with respect to the model parameters and updates the parameters in the 
  ▎ opposite direction. The learning rate controls the step size..."

  This gets returned as state["hyde_doc"].

  ---
  How It's Used

  In registry.py: _build_rag_payload(), the HyDE passage is prepended to the 
  user prompt sent to RAG Agent:

  if hyde_doc:
      user_prompt = (
          f"{query}\n\nHypothetical relevant content:\n{hyde_doc}"
      )

  So the RAG Agent's embedding model encodes this richer text (query +
  hypothetical passage) when searching the PDF, instead of the short raw query
  alone.

  ---
  Why It Helps

  The core problem:

  Short query embedding:   "gradient descent"
                                ↓
                      [tiny vector, weak signal]
                                ↓
                      Retrieves loosely related chunks

  HyDE embedding:     "Gradient descent is an iterative optimization
                       algorithm used to minimize a loss function..."
                                ↓
                      [rich vector, strong signal]
                                ↓
                      Retrieves the right textbook sections

  A 3-word query has a sparse embedding. The hypothetical passage has the same
  vocabulary and style as the target document, so its embedding is much closer
  to the relevant PDF chunks in vector space.

  ---
  When It's Triggered

  From agent.py: _route_after_plan_learning_path():

  if "RAG_AGENT" in plan.required_agents:
      if len(query.split()) < 10 or confidence < 0.85:
          return "generate_hyde_doc"   # use HyDE
  return "dispatch_agents"             # skip HyDE

  Two conditions — either is enough to trigger it:

  ┌─────────────────────────────┬───────────────────────────────────────────┐
  │          Condition          │                  Reason                   │
  ├─────────────────────────────┼───────────────────────────────────────────┤
  │ Query has fewer than 10     │ Short queries produce weak embeddings     │
  │ words                       │                                           │
  ├─────────────────────────────┼───────────────────────────────────────────┤
  │ Learner level confidence <  │ Uncertain level → vague phrasing → weak   │
  │ 0.85                        │ embedding                                 │
  └─────────────────────────────┴───────────────────────────────────────────┘

  If RAG is not in the plan at all (e.g. no PDFs uploaded), HyDE is completely
  skipped.

  ──────────────────              ────────────────────────────

  "teaching"         ──────────►  Teaching Agent consumer

  ───────────────────────────    ───────────────────
  "rag-complete"     ──────────►  PlannerKafkaClient.collect_agent_responses()
  "material-compiled"──────────►  PlannerKafkaClient.collect_agent_responses()
  "quiz-complete"    ──────────►  PlannerKafkaClient.collect_agent_responses()

      agent_type="RAG_AGENT",

  ---
  LangGraph State is Pure In-Memory

  The PlannerState TypedDict just holds Python objects — it never touches Kafka:

  PlannerState = {
      message: PlannerMessage,
      learner_profile: LearnerProfile,
      learning_plan: LearningPlan,
      agent_responses: {          ← filled by collect_responses node
          "RAG_AGENT": {...},
          "TEACHING_AGENT": {...},
      },
      synthesized_content: "...", ← filled by synthesize_response node
      ...
  }

  LangGraph routes between nodes using this dict. Kafka is only called inside 
  two specific nodes:

  ┌──────────────────────────────┬───────────────────────────────────────────┐
  │             Node             │               Kafka action                │
  ├──────────────────────────────┼───────────────────────────────────────────┤
  │ _node_dispatch_agents        │ produces to rag, teaching, quiz topics    │
  ├──────────────────────────────┼───────────────────────────────────────────┤
  │ _node_collect_responses      │ polls rag-complete, material-compiled,    │
  │                              │ quiz-complete                             │
  ├──────────────────────────────┼───────────────────────────────────────────┤
  │ _node_produce_clarification  │ produces to clarify-user-level topic      │
  ├──────────────────────────────┼───────────────────────────────────────────┤
  │ _node_wait_for_clarification │ polls user-clarification-response topic   │
  ├──────────────────────────────┼───────────────────────────────────────────┤
  │ _node_emit_result            │ produces to planner-response topic        │
  └──────────────────────────────┴───────────────────────────────────────────┘

  Every other node — validate, classify, guardrail, rewrite, HyDE, synthesize —
  is pure Python, no Kafka.

● File-by-File Flow: Start to End

  ---
  STEP 0 — Process Starts

  File: worker.py
  PlannerWorker.start()
    └── creates KafkaProducer + KafkaConsumer  (kafka_client.py)
    └── creates PlannerAgent(config, kafka_client)  (agent.py)
    └── launches _poll_loop() thread

  _poll_loop()
    └── consumer.poll("init-planner" topic)  ← waits here
    └── when message arrives → _handle_record(record)
          └── PlannerMessage.model_validate(payload)  (project/schemas.py)
          └── agent.run(message)  ← hands off to agent.py

  ---
  STEP 1 — LangGraph Starts

  File: agent.py
  PlannerAgent.run(message)
    └── _initial_state(message)   ← builds empty PlannerState dict
    └── self._graph.invoke(state) ← LangGraph takes over, runs nodes in sequence

  ---
  STEP 2 — Node: validate_query

  File: agent.py → calls validator.py
  _node_validate_query(state)
    └── validator.validate_query(message, max_query_length)
          checks: request_id is UUID, query non-empty,
                  schema_version supported, session_id/user_id present
          returns: list of error strings

    if errors:
        state["input_valid"] = False
        state["errors"].extend(errors)

  ROUTING (_route_after_validate_query):
    input_valid == False  →  jump straight to emit_result  (skip everything)
    input_valid == True   →  go to assess_learner_level

  ---
  STEP 3 — Node: assess_learner_level

  File: agent.py → calls classifier.py → calls llm_client.py
  _node_assess_learner_level(state)
    │
    ├── classifier.detect_complexity(query)          ← NO LLM, pure heuristic
    │     checks: word count < 5, injection patterns,
    │             2+ multi-intent connectors, short question
    │     returns: "SIMPLE" or "COMPLEX"
    │     state["complexity"] = result
    │
    └── classifier.assess_learner_level(query, context, config)
          └── prompts.LEARNER_LEVEL_PROMPT.format(...)
          └── llm_client.call_llm_json(messages, config)
                └── _call_azure(messages, config)   ← Azure OpenAI call #1
          returns: LearnerProfile(level, confidence, reasoning)
          state["learner_profile"] = profile

  ROUTING (_route_after_assess_learner_level):
    confidence < 0.65 AND not already clarified  →  produce_clarification
    confidence >= 0.65                           →  check_guardrails

  ---
  STEP 4 (conditional) — Node: produce_clarification

  File: agent.py → calls llm_client.py → calls kafka_client.py
  _node_produce_clarification(state)
    └── prompts.CLARIFICATION_PROMPT.format(user_query)
    └── llm_client.call_llm_json(...)   ← Azure OpenAI call #2
          returns: {question, context}
    └── kafka.produce("clarify-user-level", ClarifyUserLevelMessage)
          ← KAFKA WRITE: sends question to frontend
    state["clarification_asked"] = True

    (fixed edge) → wait_for_clarification

  STEP 5 (conditional) — Node: wait_for_clarification

  File: agent.py → calls kafka_client.py → calls classifier.py
  _node_wait_for_clarification(state)
    └── kafka.wait_for_clarification(request_id, timeout=120s)
          ← KAFKA READ: polls "user-clarification-response" topic

    if timeout:
        state["learner_profile"] = intermediate / confidence=0.6
    else:
        classifier.assess_learner_level(query + user_answer, ...)
            └── llm_client.call_llm_json(...)   ← Azure OpenAI call #3
        state["learner_profile"].confidence += 0.2

    (fixed edge) → check_guardrails

  ---
  STEP 6 — Node: check_guardrails

  File: agent.py → calls guardrails.py → calls classifier.py + llm_client.py
  _node_check_guardrails(state)
    └── guardrails.check_guardrails(query, complexity, config)
          │
          ├── classifier.contains_injection_pattern(query)  ← heuristic, no LLM
          │     if match → return BLOCKED immediately
          │
          ├── if complexity == "SIMPLE":
          │     return ALLOWED  ← no LLM call (fast path)
          │
          └── if complexity == "COMPLEX":
                prompts.GUARDRAIL_PROMPT.format(user_query)
                llm_client.call_llm_json(...)   ← Azure OpenAI call #3 or #4
                returns: {result: ALLOWED|WARN|BLOCKED, reasoning}

    state["guardrail_result"] = result
    state["guardrail_reasoning"] = reasoning

  ROUTING (_route_after_check_guardrails):
    BLOCKED              →  emit_result  (stop pipeline)
    COMPLEX or short     →  rewrite_query
    SIMPLE + long enough →  plan_learning_path

  ---
  STEP 7 (conditional) — Node: rewrite_query

  File: agent.py → calls rewriter.py → calls llm_client.py
  _node_rewrite_query(state)
    └── rewriter.rewrite_query(query, learner_level, config)
          └── prompts.QUERY_REWRITE_PROMPT.format(user_query, learner_level)
          └── llm_client.call_llm_json(...)   ← Azure OpenAI call
                returns: {rewritten_query, reasoning}
          if rewritten != original:
              state["rewritten_query"] = rewritten

    (fixed edge) → plan_learning_path

  ---
  STEP 8 — Node: plan_learning_path  ← AGENT CALL DECISION MADE HERE

  File: agent.py → calls llm_client.py → uses registry.py
  _node_plan_learning_path(state)
    └── prompts.LEARNING_PLAN_PROMPT.format(query, learner_level,
  available_files)
    └── llm_client.call_llm_json(...)   ← Azure OpenAI call
          returns: {
            required_agents: ["RAG_AGENT", "TEACHING_AGENT"],
            parallel_groups: [["RAG_AGENT", "TEACHING_AGENT"]],
            depth: "conceptual",
            objective: "...",
            reasoning: "..."
          }

    validation (in agent.py):
      - only keep agents that exist in registry  (registry.py)
      - if RAG_AGENT selected but no files → remove RAG_AGENT
      - if list empty after filtering → fallback to ["TEACHING_AGENT"]

    state["learning_plan"] = LearningPlan(required_agents=[...])

  ROUTING (_route_after_plan_learning_path):
    RAG_AGENT in plan AND (query < 10 words OR confidence < 0.85)
                         →  generate_hyde_doc
    otherwise            →  dispatch_agents

  ---
  STEP 9 (conditional) — Node: generate_hyde_doc

  File: agent.py → calls hyde.py → calls llm_client.py
  _node_generate_hyde_doc(state)
    └── hyde.generate_hyde_doc(query, config)
          └── prompts.HYDE_PROMPT.format(user_query, topic_area)
          └── llm_client.call_llm_json(...)   ← Azure OpenAI call
                returns: {passage: "hypothetical textbook excerpt..."}
    state["hyde_doc"] = passage

    (fixed edge) → dispatch_agents

  ---
  STEP 10 — Node: dispatch_agents  ← KAFKA WRITES TO SPECIALIST AGENTS

  File: agent.py → calls registry.py + payload_builder.py + kafka_client.py
  _node_dispatch_agents(state)
    └── for each agent in learning_plan.required_agents:

          entry = registry.get(agent_type)   (registry.py)
            returns: AgentRegistryEntry {
              produce_topic, consume_topic,
              input_contract_builder
            }

          payload = payload_builder.build_payload(entry, state)
            └── entry.input_contract_builder(state, retry_hint)
                  RAG_AGENT     → registry._build_rag_payload()
                                    {request_id, user_prompt+hyde_doc,
  file_paths}
                  TEACHING_AGENT→ registry._build_teaching_payload()
                                    {request_id, user_query, learner_level,
  rag_material}
                  QUIZ_EVAL_AGENT→registry._build_quiz_payload()
                                    {request_id, topic, learner_level,
  num_questions}

          kafka.produce(entry.produce_topic, payload)
            ← KAFKA WRITE: "rag" / "teaching" / "quiz" topics

    state["dispatched_agents"] = ["RAG_AGENT", "TEACHING_AGENT"]
    state["pending_agents"]    = ["RAG_AGENT", "TEACHING_AGENT"]

    (fixed edge) → collect_responses

  ---
  STEP 11 — Node: collect_responses  ← KAFKA READ, WAITS FOR AGENTS

  File: agent.py → calls kafka_client.py
  _node_collect_responses(state)
    └── topic_map = {
          "rag-complete":      "RAG_AGENT",
          "material-compiled": "TEACHING_AGENT",
        }
    └── kafka.collect_agent_responses(topic_map, request_id, timeout=120s)
          ← KAFKA READ: polls all response topics simultaneously
          ← blocks here until all agents reply OR timeout
          returns: {
            "RAG_AGENT":       {compiled_material: "...", status: "complete"},
            "TEACHING_AGENT":  {teaching_content:  "...", status: "complete"},
          }

    state["agent_responses"].update(responses)
    state["pending_agents"] = []

    (fixed edge) → validate_responses

  ---
  STEP 12 — Node: validate_responses

  File: agent.py → calls validator.py
  _node_validate_responses(state)
    └── for each agent in dispatched_agents:
          validator.validate_agent_response(response, agent_type, request_id,
  min_length)
            checks: request_id matches, status != failed,
                    primary field non-null, length >= 100 chars

          if invalid AND retries remaining:
              agents_to_retry.append(agent_type)
              state["retry_rejection_reasons"][agent_type] = error

    state["agents_to_retry"] = agents_to_retry

  ROUTING (_route_after_validate_responses):
    agents_to_retry is not empty  →  retry_agent  (loops back)
    agents_to_retry is empty      →  synthesize_response

  STEP 12b (conditional loop) — Node: retry_agent

  File: agent.py → calls registry.py + payload_builder.py + kafka_client.py
  _node_retry_agent(state)
    └── increments agent_retry_counts[agent_type]
    └── builds payload with retry_hint:
          "[RETRY 1/3] Previous response was rejected: too short. Please
  provide..."
    └── kafka.produce(entry.produce_topic, payload)  ← KAFKA WRITE again
    state["pending_agents"] = agents_to_retry

    (fixed edge) → collect_responses  ← loops back to step 11
    (max 3 retries, then error recorded and moves on)

  ---
  STEP 13 — Node: synthesize_response

  File: agent.py → calls synthesizer.py → calls llm_client.py
  _node_synthesize_response(state)
    └── synthesizer.synthesize_response(query, learner_level, agent_responses,
  config)
          └── _build_content_blocks(agent_responses)
                formats RAG material, teaching content, quiz questions
                into labeled Markdown sections
          └── prompts.SYNTHESIS_PROMPT.format(query, learner_level,
  agent_content)
          └── llm_client.call_llm(...)   ← Azure OpenAI call (returns raw
  Markdown)

          if LLM fails → _fallback_concatenation()
              plain Markdown sections without LLM synthesis

    state["synthesized_content"] = markdown_response

    (fixed edge) → emit_result

  ---
  STEP 14 — Node: emit_result  ← FINAL KAFKA WRITE

  File: agent.py → calls kafka_client.py
  _node_emit_result(state)
    └── _derive_status(input_valid, guardrail_blocked, content, errors, ...)
          "complete"  = content present + all agents responded + no errors
          "partial"   = content present but some errors or missing agents
          "failed"    = blocked or no content

    └── PlannerResponse(
          request_id, session_id, user_id,
          learner_level, learning_plan,
          synthesized_content,
          study_material (from RAG),
          quiz (from QUIZ_EVAL_AGENT),
          status, errors
        )

    └── kafka.produce("planner-response", response)
          ← KAFKA WRITE: final response to frontend

    state["output"] = response
    (fixed edge) → END

  ---
  STEP 15 — Back in worker.py

  agent.run(message) returns PlannerResponse
  _handle_record() completes
  _poll_loop() loops back → waits for next "init-planner" message
